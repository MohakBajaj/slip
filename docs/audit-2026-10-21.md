# Audit 2026-10-21

Three passes over `src/`, `scripts/`, the Electron build and release config, and CI. Correctness and security, code quality, and the poteto standard. This list is the merge. A finding is here only when the code shows the failure. Severity is the effect on a user or on the next release, not the size of the diff.

No Critical findings.

High and Medium items are fixed on this branch. Low items are recorded and left.

## High

### Frontmatter dates and quoted false flags

Status. Fixed.

Location. `src/shared/markdown-file.ts:45` (`asTime`), `src/shared/markdown-file.ts:52` (`asFlag`), `src/shared/markdown-file.ts:95` (`parseSlip`).

Evidence. gray-matter parses an unquoted ISO timestamp as a `Date`. Measured on `created: 2026-01-02T03:04:05.006Z`. The old reader kept only strings, so a `Date` became "now" on the next write. The same parse leaves `done: "false"` as the string `"false"`. `Boolean("false")` is `true`, so a hand-edited flag marked the slip done. `SKILL.md` documents the unquoted timestamp form, so agent and hand edits hit this on the next save.

Fix. `asTime` calls `toISOString` on a real `Date`. `asFlag` is `value === true` only. `src/shared/markdown-file.test.ts` covers both.

### The updater deletes Slip.app before the new copy is in place

Status. Fixed.

Location. `src/shared/update.ts:447` (`applyUpdateScript`).

Evidence. The old script removed `$dest` and then moved the staged app into that path. A crash between those two commands left no `Slip.app`. The log line is still `log="/tmp/slip-update.log"` at line 449. That symlink case is the Low below.

Fix. Copy into `${dest}.slip-new`, rename the live app to `${dest}.slip-old`, then move the stage into place, then delete the old app. If a later run finds no dest and a stage, it finishes that move. If it finds no dest and only the old app, it moves the old app back and continues the install. `src/shared/update.test.ts` runs the script twice, including a retry after the dest is already gone.

### Undo rewrites slips the action did not change

Status. Fixed.

Location. `src/renderer/src/app.tsx:164` (`remember`). The write is `src/vault.ts:440` (`restoreSlips`).

Evidence. `remember` stored a snapshot of every slip. `restoreSlips` writes every slip in that snapshot. Tag, pin, and section edits do not replace the snapshot (`patchLabel` returns null for them). Undo then wrote the old copies over later edits, including edits made outside the app.

Fix. The snapshot keeps only the ids that action changed. A new slip records the id to drop. A delete records the slips to restore. `src/vault.test.ts` restores one slip and checks that a later edit on another slip stays.

## Medium

### A slip refresh loads settings from a stale snapshot

Status. Fixed.

Location. `src/renderer/src/app.tsx:134` (`reloadSlips`), `src/renderer/src/app.tsx:146` (`onSettings`).

Evidence. `onSlipsChanged` used to call a reload that did `setSettings` from `load()`. `writeSettings` updates React state and then calls `saveSettings` without waiting. A load that started before the edit can return the old settings and write them back on the next edit.

Fix. A slip refresh sets slips only. The inbox applies settings from `onSettings`, which the main process already broadcasts.

### HTML image fetch trusts DNS names and used to read file URLs

Status. Fixed.

Location. `src/shared/image-fetch.ts:136` (`addressesAllowed` inside `fetchHop`). `src/main/capture.ts:421` (`isRemoteImageUrl`).

Evidence. `isAllowedImageUrl` returns true for any hostname that is not a literal IP, so `127.0.0.1.nip.io` passed the string check and the fetch connected to loopback. `collectHtmlImages` also `readFileSync`'d `file://` images with an image extension and no size cap.

Fix. Before each request, resolve the name and reject the fetch when any record is in the block list, including IPv4-mapped IPv6. Capture fetches only `http` and `https` URLs. `src/shared/image-fetch.test.ts` stubs DNS for `127.0.0.1.nip.io` and expects no request. `src/shared/clipboard-html.test.ts` expects `file://` and `data:` to be local.

### Clipboard image embed read any path

Status. Fixed.

Location. `src/main/index.ts:119` (`embedImage`). The patch gate is `src/main/index.ts:2044` (`acceptedPatch`).

Evidence. `parseSlip` kept every image string. `copyBundle` passed those strings to `embedImage`, which read the path with `readFileSync`. A slip could name `/dev/zero` or any other file the process can read.

Fix. `embedImage` accepts a path only when `resolveAttachment` confines it to `vault/attachments`. A file `nativeImage` cannot decode is read only when `attachmentType` starts with `image/`. An `updateSlip` or `updateSlips` patch is dropped when any image path fails that check. Restore does not require the files to exist yet, because undo puts them back from `.trash`.

### A markdown file was a slip, and a failed write still looked saved

Status. Fixed.

Location. `src/shared/markdown-file.ts:64` (`SLIP_FILE`), `src/shared/markdown-file.ts:95` (`parseSlip`). `src/vault.ts:69` (`writeSlipFile`), `src/vault.ts:342` (`updateSlips`).

Evidence. `parseSlip` accepted any `.md` body the caller had not already skipped (`INDEX.md`, `SKILL.md`). The id came from frontmatter, so it could disagree with the filename. `writeSlipFile` returned without writing when the id or filename failed its check, and `updateSlips` still returned the patched object.

Fix. `parseSlip` returns null unless the filename matches `YYYY-MM-DD-<6 id>.md`, and the id is the one in the filename. `writeSlipFile` returns false when it does not write. `updateSlips` keeps the old slip in that case.

### A missing index was a stub

Status. Fixed.

Location. `src/vault.ts:162` (`ensureVault` writes `renderIndex`).

Evidence. A missing `INDEX.md` was written as `# Slip index\n`, so the index no longer listed the slips already on disk.

Fix. The first write is `renderIndex(readSlips(root))`. `src/vault.test.ts` deletes the index and expects the slip title after `listSlips`.

### IPC accepted a renderer object as a slip

Status. Fixed.

Location. `src/main/index.ts:2044` (`acceptedPatch`), `src/main/index.ts:2095` (`restoreSlips`). Parsers are `src/shared/markdown-file.ts:189` (`slipPatch`) and `src/shared/markdown-file.ts:226` (`slipRecord`).

Evidence. `updateSlip`, `updateSlips`, and `restoreSlips` trusted the renderer payload. `applyPatch` spread every field except `id`, `filename`, and `updatedAt`.

Fix. `slipPatch` keeps booleans for `archived`, `done`, and `pin`, strings for `content` and `section`, and string arrays for `images` and `tags`. A present field of the wrong type rejects the whole patch. `slipRecord` requires a full slip whose `id` matches the filename. Unknown keys are ignored. Vault functions still take `Partial<Slip>` and `Slip`.

### A release crash between commit and tag bumps again

Status. Fixed.

Location. `scripts/cut-release.ts:72`. The predicate is `src/shared/changelog.ts:113` (`releaseTagPending`).

Evidence. `cut-release` writes the version, commits `Bump version to X.`, then tags. A crash after the commit and before the tag made the next run treat that commit as a new release and bump again.

Fix. When `HEAD` is `Bump version to <current>.` and `v<current>` does not exist, the script tags the current version and exits. `src/shared/changelog.test.ts` checks the predicate.

### The swap test locked the script text

Status. Fixed.

Location. `src/shared/update.test.ts` (the case "the swap replaces the app and finishes a move that stopped halfway").

Evidence. The old test searched the script string for `rm -rf "$dest"`, `kill -0`, and `open`. That fails when the script changes and still passes when the swap does not install the app.

Fix. The test builds two fake `Slip.app` trees, stubs `ditto`, `xattr`, and `open`, runs the script, and checks the installed marker, the opened file, and a retry that finishes a half-moved stage.

## Low

### The update log is a fixed path in /tmp

Status. Not fixed.

Evidence. The script appends to `/tmp/slip-update.log`. A symlink planted there before the swap receives the log.

Fix. Open a log file under the user temp directory created for that swap, or skip the file and let the parent capture stdout.

### The parakeet fetch has no checksum

Status. Not fixed.

Location. `scripts/fetch-parakeet.sh:38`.

Evidence. The script downloads a GitHub release tarball and copies `parakeet-cli` into `resources/bin` with no SHA-256 check. The app updater does check the zip (`assessDownload` in `src/shared/update.ts`). This script is the maintainer download.

Fix. Pin the expected digest next to the URL and refuse a mismatch before the copy.

### Capture chords are five copies of the same reset

Status. Not fixed.

Evidence. Each hit resets the other matchers and calls its own callback. The current function resets every matcher that did not fire. No current miss or double-fire is proven.

Fix. One list of matcher plus callback, and one reset of the rest. Do that when a sixth chord is added. A refactor now moves the branches.
